# `src/Audio/Native/Visualizer/` — the music visualizer

The experimental MilkDrop visualizer behind the **Music Visualizer for Themes** setting, shown by the
`UPS_MusicVisualControl` theme element. Packaged into the `.pext` under `Visualizer\` by
`scripts/package_extension.ps1`, and found at run time next to `UniPlaySong.dll` by
[`MusicVisualControl.cs`](../../../Controls/MusicVisualControl.cs).

Full manifest with SHA-256, provenance and licence for every shipped binary:
[`SHIPPED_BINARIES.md`](../../../../docs/dev_docs/SHIPPED_BINARIES.md).

## This folder

| File | What it is | Arch | Source | Licence |
|---|---|---|---|---|
| `UniPlaySongVisualizer.exe` | The renderer: draws the preset with projectM into an offscreen OpenGL surface and hands each frame to Playnite through shared GPU textures. Its own process because projectM and OpenGL need a 64-bit address space and a GL context, neither of which belongs inside Playnite. | x64 | **First-party** — [`native/visualizer/renderer.cpp`](../../../../native/visualizer/renderer.cpp) | MIT |
| `UniPlaySongVisualizerBridge.dll` | Loaded into Playnite's 32-bit process. Opens the renderer's shared textures through Direct3D 9Ex and copies the newest into the surface WPF's `D3DImage` shows - GPU to GPU. | x86 | **First-party** — [`native/visualizer/bridge.cpp`](../../../../native/visualizer/bridge.cpp) | MIT |
| `projectM-4.dll` | [projectM](https://github.com/projectM-visualizer/projectm) 4.1.8, the MilkDrop-compatible engine. Used only by the renderer. | x64 | Built from [`lib/source/projectm-source-4.1.8.tar.gz`](../../../../lib/source/) | **LGPL-2.1** (see below) |
| `glew32.dll` | [GLEW](https://github.com/nigels-com/glew) 2.2.0, OpenGL extension loading for projectM and the renderer. A DLL on purpose: projectM never calls `glewInit()` itself, so it must share the one GLEW the renderer initialises. | x64 | Built from [`lib/source/glew-source-2.2.0.tgz`](../../../../lib/source/) | Modified BSD + MIT + Khronos |
| `presets/UPS - Glow Bars.milk` | The one style that ships. Written for UniPlaySong, generated by [`native/visualizer/presets/make_presets.py`](../../../../native/visualizer/presets/make_presets.py) along with four more not shipped yet. | - | **First-party** | MIT |

**Why a 64-bit exe in a 32-bit plugin.** Playnite is x86, so everything it loads must be x86 - that is the
bridge. The renderer runs as its own x64 process, so it can use what it likes; it sits in this subfolder rather
than beside the plugin DLLs so nothing ever tries to load it into Playnite. It exits when Playnite does, even
after a crash (it is given Playnite's process id and watches it).

**No Visual C++ runtime needed.** Everything is built with the static MSVC runtime (`/MT`). The only imports are
Windows system DLLs (`d3d11`, `d3d9`, `opengl32`, `user32`, `gdi32`, `kernel32`) - check with
`dumpbin /dependents`.

## LGPL compliance (projectM)

projectM is LGPL-2.1; UniPlaySong is MIT. The combination is fine because:

1. **Dynamic linking.** `projectM-4.dll` is a separate file the renderer loads; it can be replaced with any
   compatible build of projectM 4.1.x.
2. **Source in the repo.** [`lib/source/projectm-source-4.1.8.tar.gz`](../../../../lib/source/) is the `v4.1.8`
   tag with its `projectm-eval` submodule, so the exact source stays available even if upstream moves. Only
   `docs/` and the 9 MB `background.png` (no build input) are left out; the complete tag is at
   <https://github.com/projectM-visualizer/projectm/tree/v4.1.8>.
3. **Notices** in the top-level `NOTICES.txt`.

No GPL code: projectM 4.1.8's vendored pieces are MIT (projectm-eval, hlslparser, glm), public domain (SOIL2, stb)
and Apache-2.0 (`etc1_utils`, inside SOIL2). Community MilkDrop preset packs carry no licence and are never
bundled - the shipped preset is UniPlaySong's own.

## Rebuild

```
native\visualizer\build_deps.cmd   rem GLEW + projectM from lib\source, into native\visualizer\obj\deps
native\visualizer\build.cmd        rem renderer + bridge, copies everything here
```

Visual Studio 2022 (C++) and CMake. Details, flags and the shared-memory layout:
[`VISUALIZER_ENGINE_BUILD.md`](../../../../docs/dev_docs/features/VISUALIZER_ENGINE_BUILD.md).

## ⚠️ Unsigned and self-built

No Authenticode signature on any of these. A process that renders offscreen with OpenGL and shares GPU memory
with another process is unusual enough that a heuristic engine may flag it. Verify independently: hash the files
against the manifest, rebuild them from the sources above, or delete this folder - that turns the visualizer off
and nothing else (the element stays empty).
